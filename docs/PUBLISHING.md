# GitHubに載せる範囲

このフォルダーは一般化したソース一式。元の個人向け開発フォルダーやアプリの保存フォルダーを混ぜない。公開する場合はこのフォルダーをリポジトリのルートにする。

## 含めるもの

`source-files.txt` に、アプリのソース、架空データの試験、ビルド設定、説明書、公開用の自動試験設定を列挙している。追加ファイルは内容を確認してからこの一覧にも追加する。

ソースZIPを作るには:

```powershell
./tools/package-source.ps1
```

`.artifacts/source/` にZIPとSHA-256ファイルができる。ZIPには一覧に書かれたファイルだけが入り、`.git`、ビルド結果、ローカル試験ログは含まれない。ソースZIPは、ダブルクリックでアプリを起動するための配布物ではない。

`.gitignore` はよくあるデータ・鍵・ログ・生成物を除外する補助。任意の文書に含まれる秘密情報まで検出するものではない。ZIPの対象一覧とGitへの追加対象は別なので、公開前に両方を確認する。

## 公開前の確認

1. 対象ファイルと、追加する履歴・タグに、実業務の内容、個人情報、認証情報、個人の実パス、スクリーンショットがないことを確認する。
2. `tools/build.ps1 -Publish` を実行し、試験結果を確認する。ライセンスは未指定のままとし、第三者ライブラリの表示と区別する。
3. 実際に使うGitHubアカウント・リポジトリ名・公開範囲を確定してからアップロードする。公開用に別途作成したソースの履歴を使い、元の個人用作業フォルダーの履歴を持ち込まない。

既存のリポジトリへ追加する場合は、そのリポジトリの過去のコミットも別途確認する。今回のソース点検だけでは、追加先の過去履歴は確認できない。

## 実行ファイルの公開

[WAREHITO/TaskAssist](https://github.com/WAREHITO/TaskAssist) が公開先。ライセンスは未指定。既存リポジトリへの新規コミットは、公開用の作者名とGitHubの非公開用メールを確認して作る。ブラウザーのアップロードで登録メールが公開される設定の場合は、そのまま確定しない。

`tools/build.ps1 -Publish` の出力を `tools/package-runtime.ps1 -PublishDirectory` へ渡し、実行ファイルと必要な部品を含むZIP・SHA-256を作る。中身を点検してからGitHub Releasesへ公開する。`TaskAssist.exe`単体は配布単位ではない。ローカルの業務DBやアプリ設定を混ぜない。

1.0.0-rc.2 は接続検証版。公開時にはpre-releaseとして実機未検証の範囲を明記する。ソースのpush、Actions成功、Releaseのアップロード成功は、それぞれ実際の結果を確認する。認証・権限エラーを公開成功と扱わない。

GitHub上でワークフローが有効なら、公開後のpush等でビルド・架空データ試験が実行され、ログがGitHub上に残る。このため、後から実業務データを試験ファイルに加えない。
